# 光刻版缺陷复核服务（photomask-defect-audit）

对轴对齐污染框集合计算**并集面积**与**外露周长**。重叠、相切、完全包围
都只计一次；内部接缝（含覆盖 2→1 的缝）不计入清洗边界。

## 接口

### `POST /api/audit`

请求体为 1–50000 个矩形的 JSON 数组（也接受 `{"rectangles": [...]}`）：

```json
[
  {"id": "a", "x1": 0, "y1": 0, "x2": 3, "y2": 2},
  {"id": "b", "x1": 1, "y1": 1, "x2": 4, "y2": 3}
]
```

约束：`id` 为非空字符串且**全局唯一**（几何重复允许、标识重复拒绝）；
四个坐标为 `|v| ≤ 1e9` 的整数，且 `x1 < x2`、`y1 < y2`。

成功 `200`（结果以十进制字符串返回，任意精度）：

```json
{"area": "10", "perimeter": "14"}
```

失败 `400`：带输入位置的稳定错误，**不夹带任何部分结果**：

```json
{
  "error": {
    "code": "invalid_rectangle",
    "message": "rectangles[1]: duplicate id 'x' (id must be unique)",
    "location": {"index": 1, "id": "x"}
  }
}
```

### `POST /api/separation-audit`

在**同一组合法矩形**（每个矩形额外带正整数 `cost`，1–160 个）外加两个
整数取样点，裁决使两点不再能沿污染区域通行的**全局最小代价清洗集**：

```json
{
  "rectangles": [
    {"id": "a", "x1": 0, "y1": 0, "x2": 2, "y2": 2, "cost": 50},
    {"id": "b", "x1": 2, "y1": 0, "x2": 4, "y2": 2, "cost": 1},
    {"id": "c", "x1": 4, "y1": 0, "x2": 6, "y2": 2, "cost": 50}
  ],
  "start": {"x": 0, "y": 0},
  "end":   {"x": 6, "y": 0}
}
```

连通关系以**闭合矩形的非空交集**建立：共边（一维相接）与共点（角点相接）
都算连通，不以面积重叠代替。几何重复的框标识不同即互为独立来源，
必须分别清除。

成功 `200`——已隔离：

```json
{
  "status": "separated",
  "removed": ["b"],
  "total_cost": "1",
  "reachable_from_start": ["a"]
}
```

`removed` 为精确最小总代价的清洗框标识；同代价时取**升序标识列表
字典序最小**的方案。`reachable_from_start` 是清除后从起点仍可达的
框标识分区，可据其与终点覆盖框不相交来复核隔离证据（结果以十进制
字符串返回，任意精度）。

无需/无法给方案时 `200` 返回稳定结论，**不带任何部分方案字段**：

* `{"status": "not_covered", "point": "start"|"end", ...}` —— 某取样点
  未被任何框覆盖；
* `{"status": "already_separated", ...}` —— 两点原本就不连通。

输入非法（含 `cost` 非正整数、缺取样点、框数超 160 等）返回 `400`，
错误带输入位置且不夹带部分结果。

### `GET /healthz`

仅当**请求校验器**、**扫描引擎**与**隔离裁决器**三个组件都完成启动
自检并就绪时返回 `200 {"status":"ok", ...}`，否则 `503`。
Docker 健康检查即探测此端点。

## 算法

### `/api/audit`：扫描线

横坐标归并进入/离开事件；纵坐标压缩后用线段树同步维护**覆盖计数、
覆盖总长、连续覆盖段数**（O(n log n)，5 万矩形 < 1s）。同一横坐标的
混合事件整体裁决：进入边在整组应用前的树上、离开边在整组应用后的
树上，查询该边 y 区间内"外侧未覆盖长度"作为外露竖直边——共边与内部
接缝自然计 0，仅角点接触的边也不会被吞掉。面积 = Σ 覆盖总长 × 板宽；
水平边 = Σ 2 × 连续段数 × 板宽。不铺开单位网格、不逐对切割矩形、
不调用几何求解库（纯标准库，零第三方依赖）。

### `/api/separation-audit`：全局最小权顶点割

在"闭合矩形交图"上求起点覆盖集到终点覆盖集的最小权顶点割。**顶点拆边**
把顶点割化为边割：每个框拆成 `in→out`、容量为其清洗代价；相交框对加
容量 INF 的双向弧；覆盖起点的框由超源以 INF 接入，覆盖终点的框以
INF 接入超汇。一次 **Dinic max-flow**（大整数容量）即给出全局精确
最小总代价——不逐次删除、不局部贪心、不以面积重叠建图（n ≤ 160，
O(n²) 建图，至多 O(n) 次完整网络上的可行性问答）。

同代价字典序裁决不靠枚举割集：先用一次最大流定出最小代价 C，再以
**精确可行性问答**按标识升序逐位构造答案——强制保留的框拆边容量置
INF、强制清除的框加 `S→in` 与 `out→T` 的 INF 弧，每问都在**完整图**
上求一次全局最大流问"最小割是否仍为 C"，约束只收紧可行割集，因此
得到 `(代价, 升序标识列表)` 字典序最小的唯一方案。

## 运行

```bash
# Docker（宿主机端口可配置，默认 8080）
AUDIT_HOST_PORT=9090 docker compose up --build audit

# 一次性验证：跑完即退出，退出码即结果（0 通过 / 1 失败）
docker compose up --build --exit-code-from verify verify

# 本地（无需 Docker，Python ≥ 3.11）
python3 -m app.server                 # AUDIT_PORT 可改端口
python3 -m unittest discover -s tests # 代码测试
python3 verify/run_verifier.py        # 完整验证（需服务已启动）
```

verify 服务依次执行：代码测试（unittest 全量）→ 构建检查（compileall）
→ 等待审计服务健康 → API/HTTP 冒烟（重叠框面积 10 周长 14、相邻方框
不计公共边、重复框不增量、重复标识/非法矩形带位置拒绝且无部分结果）
→ 隔离裁决冒烟（相切连通链、角点相接、端点多重覆盖两路同切、
几何重复分别清除、同代价字典序裁决、未覆盖/原本不连通稳定结论），
随后退出并以退出码报告结果。

## 目录

```
app/geometry.py     扫描线引擎 + 请求校验（核心，纯标准库）
app/separation.py   闭合交图 + 全局最小代价顶点割（拆点 Dinic + 字典序裁决）
app/components.py   组件注册表与启动自检（健康检查依据）
app/server.py       HTTP 服务（ThreadingHTTPServer）
tests/              单元 / 随机对照（枚举/网格预言机）/ 端到端 HTTP 测试
verify/             一次性验证服务
Dockerfile          审计接口镜像（含 HEALTHCHECK）
docker-compose.yaml audit + verify 编排
```
